# Project Overview

## Goal
The goal of the final project is to expose students to the real-world research and design process of doing an in-depth visualization design and implementation.

## Introduction
As part of the project, each group of 3 students will:

- Work with real datasets.
- Complete an exploratory data analyis
- Complete a task analysis.
- Design and implement an interactive visualization. 
- Solicit and incorporate feedback. 
- Communicate the final project and results through an in-class presentation and demo video.

## Detailed Requirements
The interactive web-based visualization must meet these criteria:
### TECHNOLOGY
- Be created using Altair
- Not use dashboard generation tools for the final product. E.g., no Tableau Web Player, R Shiny, Plotly Dash.
- Be usable with the latest version of Chrome.
### PROGRAMMING
- You have clear, well-commented, and well-structured code.
- Comments provide information not present in the code itself and can help organize the code.
- Proper and consistent indentation. Code inside a block is indented more than outside it.
- Code is organized in short, reusable functions and there is little to no code duplication.


### DESIGN

#### Encoding
- Include at least 5 distinct visual representations
- Have one novel hand-drawn artistic visualization
- Have at least 2 interactive views

#### Interaction
Each view must support
- support mouse-based interaction _(e.g., hover, click, drag, tooltip, scrollytelling)_
- at least one [UI widget](https://altair-viz.github.io/user_guide/interactions.html#input-element-binding) (eg. dropdown, radio button, range slider, calendar).
- at least one advance interaction technique such as brushing and linking or detail views. 

#### Presentation
- Layout should use screen space wisely. Layouts that are too sparse force the user to scroll unnecessarily. Layouts that are too dense are cluttered.
- Interface should include enough headings, legends, axis labels, and any other explanatory text needed to make it comprehensible.

#### Novelty
- For the Altair visualizations it should be a custom-designed visualization not from an off-the-shelf library. Don’t copy the entire design from an existing visualization. Individual visualization components may be copied from elsewhere (with attribution).
- In addition to the visualizations that are programmed, you will be required to submit one high-fidelity sketch of a novel visualization

#### Effective & Expressive
- Demonstrate appropriate and effective use of basic visual encodings: spatial layout, color, size, shape, etc.
- Provide a fair representation of the underlying data.
- The data / visualization should address an interesting question relevant to the partner or their users and convincingly solve target user tasks.

### DATA
- Use data set(s) with substance and depth.
- The dataset you choose must have
  - At least 12 attributes _(5 quantitative, 4 nominal, 2 ordinal, 1 temporal)_
  - At least 100 data items

### EVALUATION
Projects will be evaluated based on
- Effectiveness of visualizations and interactions, which should link back to tasks, intended audience and theoretical concepts
- Level of technical difficulty and quality of implementation
- Addresses the goals and requirements
- Quality and clarity of writing
- Teamwork 

## Teaching staff’s discretion:
Meant as a stand-in for any other characteristics not accounted for elsewhere in the rubric and for more holistic evaluation.
You get 90% of the points by meeting our expectations, but the last 10% is for doing amazing work that demonstrates your creativity and deep understanding of the course material.
Points will be deducted for not following the instructions.
